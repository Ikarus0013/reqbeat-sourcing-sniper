How to use Sourcing Sniper

A small test rig for one question: is Reqbeat's hiring data good enough to build a “pitch recruiters the moment a role opens” business on?

1Start it

Open Terminal and run:

cd ~/Desktop/reqbeattest
npm start

Then open http://localhost:4321. Leave the Terminal window open; closing it (or pressing Ctrl+C) stops the app.

Your Reqbeat key lives in the .env file as REQBEAT_API_KEY=.... The pill at the top right of the dashboard tells you whether it was picked up: “live API key” is what you want. “sandbox” means the key is missing and you are seeing a limited free sample.

After editing .env you must stop and restart the app. Changes to config.json and data/recruiters.json apply on the next run without a restart.

2Run a check

Press Run check now. It takes roughly 30 seconds. Behind the button:

  1. Trigger. One Reqbeat search per role per country (3 roles × 6 countries = 18 searches), asking only for reqs first seen in the last 7 days. Staffing agencies are filtered out.
  2. Enrich. For each company found, one lookup for its proper name. The hiring pulse arrives with the search result.
  3. Match. Every req is scored against the recruiter directory.
  4. Action. An email to the top-scoring recruiter is drafted. It is never sent.

The page keeps showing the last run until you press the button again, so reloading costs nothing. There is no schedule yet: a “daily check” today means you pressing the button once a day.

The match score

Out of 100: 50 if the recruiter specialises in that role type, 30 if they cover the country (15 if they work Europe-wide), 5 per job-title keyword they list (max 15), 5 if they place that seniority. The top scorer gets the email; under 50 means no match. It is a simple rule, not an AI model.

4What is real and what is simulated

PieceStatus
Job openings, dates, boardsReal, live from Reqbeat.
Company names and hiring pulseReal, live from Reqbeat.
Recruiter directoryMade up. 12 fictional recruiters in data/recruiters.json.
Hiring-side contactPlaceholder. Reqbeat has no people data; you would need a contact provider.
EmailsDrafted from a template. Never sent anywhere.
“Simulate send”Adds a line to the outbox log in your browser. Nothing else.

5Change what it looks for

Edit config.json in any text editor, save, press Run check now.

{
  "sender": "Ron",              ← name the emails are signed with
  "lookbackDays": 7,            ← how far back a req may have been first seen
  "perQueryLimit": 20,          ← max companies per search (25 is the ceiling)
  "enrichLimit": 60,            ← max company-name lookups per run
  "roles": [
    { "query": "ai engineer", "domain": "ai", "label": "AI Engineer" }
  ],
  "countries": ["United Kingdom", "Germany"]
}
  • query is matched against the job title, and every word must appear exactly. engineer does not match engineers. Shorter queries find more: gtm finds more than gtm engineer.
  • domain is the tag used to pair roles with recruiters (ai, gtm, infra). Add a new tag and give at least one recruiter the same tag.
  • countries must be single countries in English (“UK” and “USA” also work). Regions such as “Europe” or “EU” are rejected.
  • Each extra role or country multiplies the number of searches: roles × countries per run.

Use your own recruiters

Replace the entries in data/recruiters.json. Each one needs:

{ "id": "r1", "name": "Jane Doe", "firm": "Acme Search", "email": "jane@acme.com",
  "domains": ["ai"], "countries": ["Germany"],   ← or ["*"] for Europe-wide
  "keywords": ["llm", "agent"], "seniority": ["senior", "staff"] }

6Use it to judge Reqbeat

Run it once a day for a week and note four things:

  1. Speed. Does the “Hot” tile fill up on weekdays, and how many hours sit between a req's first-seen time and your run? Spot-check a few against the company's careers page.
  2. Volume. Fresh reqs per day for the roles you care about. Watch “By role” for searches that keep returning zero.
  3. Accuracy. Open ten signals. Are they real, still open, the right role, the right country?
  4. Cost. Calls per run from the account tile, against the plan's daily quota and price.

Gap to plan for: Reqbeat tells you which company and which role, not who to email. The contact step needs a second data source, and that cost belongs in the business case.

7If something breaks

You seeDo this
Page won't loadThe app isn't running. npm start in the project folder.
“address already in use”It is already running in another window. Run pkill -f "node server.js", then npm start.
Pill says “sandbox”Key not found. Check .env has REQBEAT_API_KEY=yourkey with no quotes or spaces, then restart.
Orange “calls failed” barOpen it to read the reason. 401/403 = bad key. 429 = quota reached, wait. 422 = a country name or limit in config.json is invalid.
Zero fresh reqsRaise lookbackDays or shorten the role queries.
